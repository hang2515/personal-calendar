# 备份设置与补签

## 用户已确认的需求

云备份采用独立设置栏与页面。上传和读取分开，不使用“预览与恢复”作为操作入口。提供自动备份开关和每天时间。允许创建日起到昨天所有历史漏签计划日补签，不允许未来或未安排日期。

## 交互与规则

- “我的 → 云备份设置”打开完整页面：立即备份、读取云备份、自动备份及账号安全。读取仅查询并显示备份日期/数量；“恢复到这部手机”需要二次确认整份替换。
- 手动备份通过用户确认的账号、云版本和本地版本执行，不自动开启自动备份。已有云内容或换账号上传时明确确认替换。
- 自动备份默认每天 22:00（北京时间），复用时间滚轮，可选择 00:00–23:59。时间是本机设置，不放入云快照。WorkManager 持久保存联网的每日任务；系统省电或断网会延后。日历修改留下本地版本，下一次计划备份读取最新内容。
- 保留 ETag 条件更新、待上传内容持久化、有限重试、账号绑定和恢复版本检查。关闭自动备份、退出、恢复取消每日任务；手动仍可独立备份。
- 日历详情中点击漏签日期，确认后补签；历史已完成日期可确认撤销以修正误操作。按目标日期的历史排期校验，重复补签不增加版本，不更改历史规则，不影响今天提醒。
- 保持 Room 结构和云快照协议；历史补签使用既有 check_ins 表与唯一键，设置时间使用本机偏好存储。没有新增 AWS 服务或第三方 UI 库。

## 验证与交付

测试先行覆盖补签日期/历史规则/幂等/月度统计/备份导出恢复、手动与自动独立、每天时间边界和任务去重/重排/取消，以及页面入口、确认、返回和原生截图。运行完整安卓测试、构建及 Lint，核验递增版本、同签名及生产配置，推送开发分支和新版 APK。

## 实施中确认的细节

- 普通 24 小时周期会跟随实际完成时间偏移，改为每轮终结后通过 `setNextScheduleTimeOverride` 和 `UPDATE` 对齐下一次北京时间；重试保留退避，不改成等到第二天再重试。回归同时验证旧任务代数的终结清理不会删除新覆盖时间。
- 关闭、退出与恢复在调度互斥锁内取消任务；不会由刚完成的旧任务重新开启备份。
- 恢复提交前再次获取云备份 ETag，变化则拒绝；本地版本仍在事务内检查。
- 全量回归暴露删除页会在 Room 流移除日历后销毁的边界。确认删除使用独立操作作用域，保证后续通知清理及返回回调完成；仓库仅持有 applicationContext。
- 用户提供截图仅用于理解需求，不复制截图或实际账号信息进公开仓库。界面截图使用测试示例账号与数据。

调度依据：[Android 周期任务覆盖时间](https://developer.android.com/reference/androidx/work/PeriodicWorkRequest.Builder#setNextScheduleTimeOverride(long))。本轮未改变 AWS 资源、云接口或快照版本，无需云端部署。

- 完整执行安卓测试、APK 构建及 Lint：55 项测试通过，0 失败、0 跳过；Lint 0 错误、12 条警告（原有 SDK/Gradle、资源、Context/KTX 提示及新偏好存储的 KTX 建议）。没有降低断言或忽略错误。

- 每日任务测试验证联网条件、24 小时间隔、时间持久化、重复安排去重、显式修改重排、关闭取消，以及延期后覆盖时间的代数保护。
