# 个人日历：原型与开发计划

更新日期：2026-10-03
GitHub 仓库：`personal-calendar`（私人仓库）

> 当前实施范围：本地无需登录 + 可选 AWS 云备份与换机恢复。采用完整快照，不做多设备实时同步。具体实施以 [AWS 云备份部署](AWS云备份部署.md) 为准。

## 1. 产品目标与第一版范围

为个人创建多个相互独立的“坚持日历”。用户可为每个日历命名，设置每天或每周指定星期、每日一次打卡和一个提醒时间；“吃药”只是第一个普通日历，不做药品、剂量或处方管理。日历展示已完成、已错过、未来待完成和未安排四种日期状态。过了当天仍未打卡的计划日自动显示为未完成；第一版不提供补签。

当前本地版无需账号，日历和打卡只保存在手机，离线可查看、打卡和接收本地提醒。用户可主动登录并开启云备份，换机时确认恢复完整快照。先提供给本人和少量测试者使用，不在这一阶段公开发布。界面使用中文、温和的浅色与鼠尾草绿，优先保证大按钮、清晰状态和无障碍可读性。

## 2. 原型

核心页面：今天、日历列表、单个日历详情、新建日历。

图片是视觉概念稿，里面的日期、完成率、账号与示例记录不代表真实逻辑或真实用户数据。实际开发以本计划中的状态规则和接口行为为准。

### 主要交互

1. 打开应用进入“今天”，按 `Asia/Shanghai` 时区列出今日计划，点“完成打卡”立即更新本地状态；保存失败时提示重试。
2. “日历”先显示不同日历的独立入口，选择后查看月历、月度完成情况及当天打卡。误打卡只能在当天撤销；删除日历前必须确认，删除时一并清除其历史记录与提醒。未安排日期不计入完成率；未来日期不显示为漏打卡。
3. 新建或编辑日历时填写名称，可选图标与颜色，选择“每天”或指定星期，设置提醒时间及开关，并实时预览。日历可暂停和恢复；暂停期间不生成计划或提醒。备注留待后续版本。
4. 到点显示 Android 本地通知，点击通知进入对应日历。通知权限或精确闹钟权限缺失时，页面说明影响并提供系统设置入口。
5. “我的”显示本机使用或当前登录邮箱、通知权限和固定北京时间说明；提供账号安全、隐私与数据、帮助与主动分享反馈，以及可选登录、备份状态、确认恢复、重新绑定与退出登录。

## 3. 技术选型

| 部分 | 选型 | 用途 |
| --- | --- | --- |
| 安卓界面 | Kotlin、Compose、Material 3 | 今天、日历、我的；最低 Android 8.0 |
| 本地数据 | Room / SQLite 版本 5 | 三张业务表和一张本地备份状态表；事务和无损迁移 |
| 本地提醒 | AlarmManager | 通知权限、精确闹钟、重启和时间变化后的重排 |
| 后台备份 | WorkManager | 联网执行、有界重试、业务修改保留后继任务 |
| 登录 | Cognito User Pool、AppAuth Android | 邮箱账号、浏览器授权码 + PKCE；令牌由 Keystore 保护 |
| 云端接口 | HTTP API、Lambda TypeScript | JWT scope 验证、归属校验、完整快照读写 |
| 云端存储 | S3 | 私有、加密、版本控制、ETag 条件写入；本期无云业务数据库 |
| 基础设施 | CDK、CloudWatch、AWS Budgets | 香港区域，开发/生产隔离，监控及费用提醒 |

## 4. 数据、接口与一致性

本地 Room 保存日历、规则历史、打卡和单行备份状态；业务时区为 Asia/Shanghai，备份时间使用 UTC。成功修改与版本递增同事务。账号绑定属于整份本地数据，不在每条业务记录上混入登录状态。

接口为 GET /v1/backup、GET /v1/backup/snapshot、PUT /v1/backup/snapshot。JSON 格式版本独立于 Room；快照最大 1 MiB，并校验日期、关联、唯一键和字段类型。传输和日志不得暴露令牌或真实记录。

首次写入使用 If-None-Match，后续使用 If-Match。网络响应丢失时重发持久化的相同快照；服务器通过完全相同内容确认幂等。冲突保留双方数据，用户预览后选择整份恢复或覆盖，不自动合并。

恢复先预览数量和时间，再确认覆盖；若本地已改变则要求重新预览。替换在单事务内完成，失败回滚，随后清理旧提醒并安排新提醒。恢复后自动备份关闭；换账号必须明确重新绑定，退出登录保留本机数据。

## 5. 开发事项与流程

1. 保留已实现的本地日历、编辑/暂停、每日打卡、撤销、删除与提醒。
2. 数据库升级为 5，完成快照导出、校验、事务恢复、版本标记与测试。
3. 用 CDK 建立测试环境，验证 API 鉴权以及部署后的 Lambda/S3 读写、隔离、幂等和版本冲突。
4. 安卓接入可选登录、云备份设置、自动与手动备份、确认恢复；通过测试、构建、Lint 和独立代码审查。
5. 部署生产环境，配置费用预警，生成公开客户端配置并重新打包。
6. 用真实账号与设备验收邮箱注册、登录回跳、后台重试、换机恢复和通知。

## 6. 验收清单

- 旧数据库升级保留日历、规则、外观、提醒与打卡，不进行破坏性重建。
- 未登录、断网及云端故障时，本地日历和提醒正常。
- 重复打卡不重复计数，上传期间的编辑仍为待备份，运行中再次编辑留下后继任务。
- 非法快照、预览过期和恢复失败不能破坏原数据。
- 匿名、错误令牌和跨账号请求不能访问他人备份。
- 旧设备不能静默覆盖新的云备份；明确确认才可恢复或重新绑定。
- API 与 Lambda/S3 联调通过不代表已完成实际账号和真机验收，分别记录结果。

## 7. 上线前提与当前默认决定

- 当前只做私人仓库和小范围测试版。AWS 全球区香港区域直接提供 HTTPS API，当前未部署 CloudFront。
- 大陆用户经全球区访问的可用性和时延必须以实测为准。正式对公众开放前，另行评估域名、数据处理、隐私与适用的上线要求。
- 第一版不做 iOS、家人代管、药品剂量、库存、云推送、补签、连续奖励或复杂统计。通知为手机本地定时通知，不承诺第三方手机系统在所有省电模式下绝对准点。
