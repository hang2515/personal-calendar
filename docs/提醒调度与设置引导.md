# 提醒调度与设置引导（0.4.4）

计划日提醒与一分钟测试通知统一由系统日历离线发送。可选闹钟模式额外登记下一次用户可见闹钟。此版本没有改动 Room 业务表和云备份协议。

## 开启与授权

开启总开关、首次开启某个日历的提醒或开启闹钟模式时显示引导：

1. 请求读写日历权限，拒绝后保持待设置，可继续请求或进入本应用权限设置。
2. 创建专属的本地“个人日历提醒”，不关联云账号，不读取其他事项。
3. 提供系统日历通知设置及打开系统日历的标准入口，声音、锁屏、悬浮由用户选择。普通模式无需本应用 POST_NOTIFICATIONS 或精确闹钟权限。
4. 开启闹钟选项时额外申请“闹钟与提醒”；未授权时系统日历仍提醒，但不伪报闹钟已登记。
5. 一分钟测试也写入系统日历。用户实际收到后点击“我已收到测试提醒”确认；时间到达或本应用回调均不能伪造成功。

系统日历通知属于另一个应用，本应用无法读取其所有渠道及厂商通知配置，因此保留检查入口和真实测试，不展示“全部通知就绪”。无系统日历应用时明确提示无法代管。

## 排期与清理

- 固定北京时间 Asia/Shanghai；每段历史/未来规则生成标准每周重复事件，不靠定期启动本应用补充短期事件。
- 今天已打卡或提醒时间已过时跳过今天；按既有规则处理明天生效的暂停和恢复。名称、提醒时间、星期、暂停、打卡、撤销、删除与备份恢复后重新投影。
- 标记包含本应用包名和源日历 ID；读写仅限本应用本地账号及专属标记，保留其他日历和用户自行添加的事项。批处理校验记录归属并保护事务；读取失败不能当作空数据清理。
- 总开关关闭前先清理代管事项。授权撤回而已有投影时，拒绝伪装为已关闭；恢复授权后重试。业务记录可正常保存，更新提醒失败在主界面及设置页提示。
- 新测试替换旧测试；关闭总开关、切换模式取消测试，用户确认后删除一次性测试事件。测试不写入业务表或云备份。
- 卸载应用不会自动删除外部日历事项。卸载前先关闭提醒，或在系统日历删除专属日历；不要删除用户的其他事项。

## 闹钟与点击边界

普通模式不注册本应用的用户可见闹钟。闹钟模式登记下一次系统标识，可从系统入口打开对应日历。系统日历负责持续重复通知；后续闹钟标识在打开本应用或打卡时更新。此选项不提供长时间铃声或全屏闹钟。

通知样式及点击行为遵循系统日历；支持标准 ACTION_HANDLE_CUSTOM_EVENT 的系统日历可从事项详情返回对应本地日历。不同厂商可能只提供系统事项详情。

## 真机证据（2026-11-09，vivo Android 16）

旧本地接收器在应用进程完全结束时被 vivo 以 `skip for auto start` 跳过；单纯允许后台耗电或使用 setAlarmClock 不能解决。旧应用的电池设置已恢复原值，未开启自启动。

系统日历路线的第一次测试在 15:20:41 唤醒系统日历，但它自身通知被关闭，系统记录 blocked=1。开启系统日历通知后，第二次测试于 15:23:08 成功登记通知“个人日历：提醒测试”，预期时间 15:23:07.635；当时本应用进程已结束、手机锁屏。本应用没有因提醒启动。

此证据证明本机系统日历可独立送达；不能替代其他手机、系统日历被禁用、通知被关闭等场景的实际测试。不要强行开启本应用自启动作为默认解决步骤。

## 安装与签名

0.4.4（构建号 10）使用 `:app:assembleRelease -PindependentInstall=true` 构建独立的“个人日历（新版）”，包名 `com.hang2515.personalcalendar.next`。需要转移旧版记录时，通过既有云备份读取、预览及确认恢复。

构建后使用维护者保存的新签名文件签署 APK。后续独立版本沿用同一包名和签名。独立应用与旧应用共用既有公开 OAuth 回调配置，并存时在系统应用选择中选新版。
